# JS Godot モバイルゲームテンプレート

[한국어](README.md) · [English](README.en.md) · **日本語**

Godot でモバイルゲームを作るとき、**ゲームの中身だけを入れれば済むように、それ以外を
あらかじめ全部作ってあるプロジェクト**です。

---

## なぜ必要なの？

ゲームを一本作るには、「ゲームそのもの」以外に作らなければならないものが山ほどあります。

- 起動したときに出るタイトル画面とボタン
- 設定画面で音量を調整する仕組み
- どこまで進んだかを保存して読み込む仕組み
- プレイ中に一時停止する仕組み
- 韓国語 / 英語 / 日本語を切り替える仕組み
- 画面がぶつ切りにならず、なめらかに切り替わる演出

やっかいなのは、これらが**どんなゲームを作ってもほとんど同じ**だということです。新しい
ゲームを始めるたびに一から作り直すのは時間の無駄ですよね。

家を建てるのに例えるなら、このプロジェクトは**骨組みが立ち、電気と水道までつながった空き家**
です。壁紙を選んで家具を置く作業 — つまり本当のゲームの中身 — だけをやればいい状態です。

## 現在の状態

- **ゲームの中身は空っぽです。** そこがあなたの埋める部分です。
- 上に挙げた土台の機能はすべて作ってあり、動きます。
- Android に実際にインストールして起動し、動作を確認済みです。
- 自動で走るチェックが 121 件、すべて通ります。

## 何が入っているの？

### 常に動いている部品

ゲームを起動した瞬間から終了するまで生き続け、どの画面からでも呼び出せる部品です。
（Godot ではこれを **autoload** と呼びます。）

| 名前 | すること |
|---|---|
| **SaveManager** | 進行状況をファイルに保存して読み込みます。保存形式が変わっても、**古いセーブファイルを自動で新しい形式に変換する**仕掛けが入っています。 |
| **Settings** | 音量と言語の設定を覚えます。セーブデータとは**別のファイル**に置いてあるので、進行状況を全部消しても設定は残ります。 |
| **AudioManager** | BGM と効果音を担当します。曲が変わるときはぶつ切りにならず、重なりながら入れ替わります。ゲームを止めても音楽は流れ続けます。 |
| **SceneManager** | 画面の切り替えを担当します。画面が暗くなってから明るくなり、次の画面へ移ります。 |
| **Services** | 広告と課金を担当する**置き場所**です。詳しくは下で説明します。 |
| **EventBus** | 部品どうしが知らせをやり取りする通り道です。詳しくは下で説明します。 |
| **DebugTools** | 開発中だけ出てくるデバッグ用の窓です。詳しくは下で説明します。 |

### 画面

起動画面 → メインメニュー → ゲーム画面がすでにつながっていて、その上に重なって出る窓
（一時停止・設定・ゲームオーバー）も作ってあります。

### そのほか

- **タッチ入力** — 軽く叩く、長押し、ドラッグ、素早く払う操作を自動で見分けます。
- **韓国語 / 英語 / 日本語** — 設定で切り替えると、再起動なしでその場で反映されます。
- **CJK フォント同梱** — フォントを一緒に入れておかないと、端末ごとに字の形が変わってしまいます。
- **ObjectPool** — 弾のように次々と現れては消えるものを、捨てずに**使い回す**仕組みです。毎回新しく作り続けるとゲームがカクつくためです。
- **Android の戻るボタン** — プレイ中は一時停止、メニューでは終了として動きます。
- **ホームボタンで外に出たとき** — 自動で停止して保存します。Android はバックグラウンドのアプリをいつでも終了させられるので、出る瞬間に保存しておかないと記録が消えます。

## いくつかの用語の説明

### EventBus — 部品どうしの連絡

「ゲームオーバーになった」ことを複数の部品が知る必要があるとします。互いを直接呼び合う
作りにすると、部品がクモの巣のように絡まり、あとで一箇所直しただけであちこち壊れます。

そこで**掲示板**を一つ置きました。知らせたいことがあれば貼り出し、気になる側が購読します。
互いの存在を知らなくて済みます。

### Services — 広告と課金の「にせもの版」

広告や課金は、Google が用意した別のソフトをつないで初めて本当に動きます。つなぐのは面倒で、
つなぐまではテストもできません。

そこで**何もせず「成功しました」とだけ返すにせもの版**を入れてあります。たとえば「広告を見て
報酬を受け取る」を押すと、広告なしですぐ報酬が入ります。おかげで本物の広告をつなぐ前でも、
ゲームの流れを最初から最後までテストできます。

あとで本物をつなぐときも、**ゲーム側のコードは一行も直す必要がありません。** にせものを
本物に差し替えるだけです。

### DebugTools — 開発用のパネル

画面の左下にある `DBG` ボタンで開きます。フレームレートの確認、好きな画面への直接ジャンプ、
言語の切り替え、セーブデータの消去ができます。

**リリース用にビルドすると、この窓はまるごと外れます。** 実際に外れることも確認済みです。

## 始め方

### 1. Godot を入れる

[godotengine.org](https://godotengine.org) から **4.7.1** を入手してください。
ほかのバージョンでは動かないことがあります。

### 2. 取得する

```bash
git clone https://github.com/JongSeok-327/js-godot-mobile-template.git
cd js-godot-mobile-template
```

### 3. 最初の準備（一度だけ・必須）

```bash
GODOT=/Applications/Godot_4.7.1.app/Contents/MacOS/Godot   # ご自身のインストール先に

"$GODOT" --headless --path . --import
```

**なぜ必要？** フォントや翻訳などのファイルは、Godot が扱いやすい形へ一度変換する必要が
あります。変換後のファイルは容量が大きく、いつでも作り直せるのでリポジトリには入れて
いません。そのため取得後に自分で一度実行します。

エディタでプロジェクトを開いても自動で行われます。

### 4. 実行

```bash
"$GODOT" --path .            # ゲームを起動
"$GODOT" --path . --editor   # エディタで開く
./tests/run_all.sh           # チェックを走らせる
```

## 自分のゲームを作る

1. **ゲームの中身を入れます。** `scenes/game/game.tscn` を開くと `Gameplay` という空の
   場所があります。その下に作ってください。
2. **新しい画面を追加したら**、`autoload/scene_manager.gd` の `SCENES` 一覧に名前を登録
   します。画面ファイルのパスをコードのあちこちに直接書かないでください — あとでファイルを
   移動すると全部探して直すはめになります。
3. **文字を追加するときは** `locale/translations.csv` に一行足します。三言語を同じ行に
   書きます。
4. **見た目を変えるなら** `ui/theme/default_theme.tres` の色と角の丸みだけ直せば、全体が
   まとめて変わります。
5. **公開前に** アプリ ID（`com.jsgame.template`）とアイコン（`icon.svg`）を変えてください。
   ⚠️ アプリ ID は**ストアに一度出すと二度と変えられません。**

## フォルダ構成

```
autoload/   常に動いている部品
scenes/     画面（起動・メニュー・ゲーム・重なる窓）
ui/         デザインテーマ、使い回す部品
scripts/    広告・課金の置き場所、タッチ入力、ユーティリティ
debug/      デバッグ窓（リリースビルドでは外れる）
locale/     翻訳ファイル
assets/     フォント、音、画像
tests/      自動チェック
```

より詳しい開発ルールと Android ビルド手順は [`CLAUDE.md`](CLAUDE.md) にあります。
