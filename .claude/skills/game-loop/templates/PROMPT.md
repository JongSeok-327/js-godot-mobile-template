# 수정 루프 — 매 반복 이 문서를 처음부터 따른다

너는 ralph 루프 안에 있다. 이 지시는 반복마다 똑같이 들어온다. **이전 반복의 기억은 파일에만 있다.**

## 1. 상황 파악 (매번)

1. `_workspace/loop/PROGRESS.md` 를 읽는다.
2. `git log --oneline -5` 와 `git status --short` 를 본다.
3. `_workspace/loop/TASKS.md` 에서 **`- [ ]` 로 시작하는 첫 줄** 하나를 고른다. 없으면 6번으로 간다.
4. 커밋 안 된 변경이 남아 있으면 이전 반복이 중간에 끊긴 것이다. PROGRESS 의 마지막 줄을 보고 이어서 끝내거나, 판단이 안 서면 되돌린다(`git checkout -- .` 와 새로 만든 파일 삭제).

## 2. 이번 반복에서 할 일: 작업 딱 하나

`game-orchestrator` 의 **흐름 1** 을 그대로 따른다. CLAUDE.md 의 계약·함정을 지킨다.

1. **재현 테스트를 먼저 쓴다.** `tests/` 에 단언을 추가하고 `./tests/run_all.sh` 로 그 단언이 **실패하는 것**을 확인한다. 실패하지 않으면 버그가 재현되지 않은 것이다 — 그 작업을 `[BLOCKED] 재현 안 됨: <관찰>` 로 표시하고 3번으로.
2. 고친다. 작업 범위 밖의 파일은 건드리지 않는다.
3. 판정: `tools/verify.sh` (새 스크립트·에셋을 만들었으면 `--import`).

## 3. 결과 기록

- **PASS** → 작업 하나를 한 커밋으로 (`git add` 는 바꾼 파일만 이름으로). 커밋 메시지에 무엇이 왜 틀렸고 어떻게 확인했는지. 그다음 `TASKS.md` 의 그 줄을 `- [x]` 로 바꾸고 이 변경도 같은 커밋에 넣는다 (`--amend` 가 아니라 처음부터 함께 add).
- **FAIL** → 원인을 고쳐 한 번 더 판정한다. **같은 작업에서 두 번째 FAIL** 이면: 변경을 되돌리고 그 줄을 `- [BLOCKED] <원문 에러 한 줄>` 로 바꾼 뒤 그 변경만 커밋한다.
- 어느 쪽이든 `PROGRESS.md` 맨 아래에 한 줄 추가하고 함께 커밋한다:
  `- 반복 N | <작업 요약> | PASS/BLOCKED | <다음 반복이 알아야 할 것 한 줄>`

## 4. 금지

- `git push`, `git reset --hard`, 브랜치 변경
- 테스트·누수 기준선·판정 스크립트를 느슨하게 고쳐 통과시키기 (진짜 기준이 바뀐 거라면 BLOCKED 로 남기고 사람이 판단하게 한다)
- `TASKS.md` 에 없는 개선·리팩터링
- 기기·아트·계정·디자인 판단이 필요한 일 (그런 작업이 목록에 있으면 `[BLOCKED] 사람 판단 필요`)

## 5. 응답 끝맺기

한 작업을 처리했으면 짧게 보고하고 응답을 끝낸다. 루프가 다음 반복을 연다.

## 6. 완료 판정

`- [ ]` 가 더 없으면 다음을 실행한다:

    .claude/skills/game-loop/scripts/loop_gate.sh

출력을 **그대로** 응답에 붙인다. 마지막 줄이 `LOOP_GATE: OPEN` 일 때만, 그리고 그때에만 응답 마지막에 다음을 쓴다:

    <promise>LOOP_DONE</promise>

`CLOSED` 면 출력된 이유를 해결한다 (커밋 안 된 변경 → 커밋, verify FAIL → 원인이 된 커밋을 찾아 고친다). 게이트 출력 없이 완료를 선언하지 않는다.
